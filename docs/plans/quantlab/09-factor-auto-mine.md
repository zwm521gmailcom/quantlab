# QuantLab 自动因子挖掘实施计划

**目标：** 建立 `/research/factor-mining`，在可审计搜索空间中生成、筛选和验证候选因子，杜绝未来函数和测试集挑选。

**依赖：** `08-factor-manual`。

## 挖掘流程

- 锁定数据版本、股票范围、训练/验证/测试时间、标签和过滤规则。
- 配置原子字段、算子白名单、窗口集合、最大表达式深度、候选上限、相关性阈值和资源预算。
- 训练期生成，验证期筛选；测试期只做最终一次评估，不参与候选选择。
- 候选保存公式 AST、父代、随机种子、数据指纹、各期指标和淘汰原因。

## 实施任务

- [x] 写搜索空间确定性、去重、未来引用拒绝、相关性剪枝和时间切分测试；验证三段真实指标、validation 筛选隔离、训练期相关性证据和候选血缘。
- [x] 第一版实现可取消并从检查点新建恢复运行的单进程 Job，不增加 `paused` 状态；取消后的原运行标记 `failed` 且原因 `cancelled`，恢复会创建新 ResearchRun 并引用原检查点，保留父运行 ID、候选去重键和日志。
- [ ] 实现配置向导、运行进度、候选排行榜、候选对比和一键转为因子草稿。
- [ ] 默认指标包括 IC/RankIC、分组收益、覆盖率、换手、稳定性和多重检验警告。
- [ ] 任何候选均不自动发布，也不自动进入回测；转为草稿时完整继承 DatasetVersion、训练/验证/测试边界、点时规则、窗口模式、表达式 AST 和父候选 ID。

## 验证与审批

- [ ] 固定种子重复运行结果一致；训练/验证/测试边界无交叉。
- [ ] 中断恢复不会重复候选或丢失审计信息。
- [ ] 浏览器可查看日志、淘汰原因和候选完整血缘。

## 2026-09-02 取消与检查点切片

- [x] `POST /api/factor-mining/jobs` 创建 queued 的同步作业，不启动后台线程。
- [x] `POST /api/factor-mining/jobs/{run_id}/checkpoint` 持久化已处理候选、去重键、游标和日志。
- [x] `POST /api/factor-mining/jobs/{run_id}/cancel` 通过既有状态机将 queued/running 作业置为 `failed`，错误原因固定为 `cancelled`。
- [x] `POST /api/factor-mining/jobs/{run_id}/resume` 创建带 `parent_run_id` 的新 ResearchRun，继承检查点并返回排除已处理去重键后的候选队列。
