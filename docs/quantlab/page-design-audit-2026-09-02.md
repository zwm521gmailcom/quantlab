## 核对标准

页面应当遵循最初系统设计：

1. 统一主导航，页面职责清楚，实体通过稳定 ID 串联。
2. 数据、因子、策略、模型、回测和结果之间有明确的版本引用关系。
3. 原始/标准数据只读，页面只显示注册信息或受限查询，不复制大表。
4. 研究和回测操作保存配置、状态、错误和产物；复制配置不得自动运行。
5. 回测结果先显示清单，再进入单条运行记录；状态、指标和文件清单可追溯。
6. 页面显示中文业务名称，内部 ID 只作为可追溯标识。

## 关键结论

### 已基本符合系统逻辑

- 核心对象和页面链路已经形成：数据注册 → 因子 → 研究 → 模型/策略 → 回测 → 运行记录 → 结果档案。
- 回测关键参数已经纳入配置冻结和运行记录，包括 SH/SZ 范围、Top 10 默认值、2 日调仓、后复权开收盘、手续费最低 5 元、基准和缺失规则。
- 结果档案与运行记录已经分工：档案负责清单，运行记录负责单条详情；状态不再单独依赖右侧统计块。
- 既有数据目录继续只读引用，没有把完整行情或因子宽表复制到网站源码目录。

### 视觉验收发现的阻断问题

1. 模型中心和策略中心没有接入统一页面壳，视觉上已经失效；这是 P0 页面一致性问题。
2. 回测中心实际路由使用未完成样式的运行版页面，而非设计稿风格的工作台页面；字段错位，核心因子、模型、过滤和仓位配置不可视。这是 P0 功能可用性问题。
3. 因子数据、因子库和系统设置在当前窄桌面视口产生横向滚动或裁切；是 P1 响应式布局问题。

### 需要列入发布前修正/核验

1. 先修复模型中心、策略中心、回测中心的统一页面壳和视觉布局，再继续其他页面优化。
2. 统一所有二级页面的共享导航、页头、返回路径和当前菜单高亮；目前手动因子、自动挖掘、策略、模型和运行记录页面的导航信息密度不完全一致。
3. 回测中心应将“默认示例配置”和“已绑定的真实版本”在视觉上明确区分，并在正式提交前显示版本门禁结果。
4. 因子数据、因子库、设置页应消除横向溢出，表格改为可横向滚动的容器或响应式列，而不是让整个页面滚动。
5. 因子研究、模型训练和回测运行页需要统一失败、部分完成、取消和跳过状态的中文展示。
6. 使用真实浏览器逐页检查：页面可达、刷新可恢复、ID 跳转、空数据、失败状态、长列表和无控制台错误。
7. 用真实数据执行一次小范围 smoke backtest，再执行一次完整年度回测；这属于运行环境验收，不应由 fixture 测试代替。
