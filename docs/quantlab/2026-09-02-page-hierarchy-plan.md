## 1. 结论

用户提出的“研究工作台信息层级 + 真实运行记录呈现”方向正确，固定展开的两级侧边栏、
“因子研究”归组、结果档案“先清单、再明细”均采纳为定稿方向。

原对照表中“当前差异”一列大多写在工作区这批未提交改动之前，部分页面已经完成实现。
同时原表未覆盖四处真实缺口：

1. 侧边栏父子激活规则未真正实现“子项高亮、父项低强度”：当前 nav.js 对父子同时施加
   强背景，且 `/factors/new/manual` 会因前缀同时点亮“因子库”。
2. 数据中心双栏 HTML/CSS 已存在，但前端没有任何代码填充“数据质量概览”和“数据集详情”。
3. 回测工作台“保存配置”与“开始回测”语义不一致：保存仍调用 `/api/backtests`，而后端
   `submit()` 会立即创建 queued BacktestRun；不存在工作台级“完整配置草稿”保存/载入链路。
4. 真实运行记录为空是数据状态问题：SQLite 中模型/策略/研究/回测运行均为 0，且工作台默认
   配置引用不存在的 dataset 版本 `v1` 与不存在的策略/模型。单靠页面改动无法产生档案行。

## 4. 验收门

- 任何页面不得出现两个同级强高亮；子页只能有“父弱 + 子强”。
- 数据中心两个新面板必须有真实内容或明确空态，不是永久占位。
- 保存配置后 `backtest_runs` 行数不增加；开始回测后才增加。
- 真实记录出现前，总览/档案保持诚实空态，不硬编码收益或状态。
- 权威数据目录与既有工作区文件不删除、不覆盖。
